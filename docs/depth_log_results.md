## Pre-specified reading, stated literally

**(b) "not resolution-like"**: Spearman rho <= 0.5 in at least one organism (E. coli rho = 0.500, n = 3; K562 rho = 0.700, n = 5). No truth was censored at the grid edge t = 256 (0 of 8; the within-1-percent interval of K562 CollecTRI reaches 256). Reading (a) was not met (needs rho >= 0.9 in both). Exact one-sided permutation P: E. coli 0.500 (smallest attainable 0.167), K562 0.117 (smallest attainable 0.008); descriptive only.

Best depths (t_best over CLR plus the geometric grid), fine to coarse:

- E. coli: operons 4, TF regulons 96, sigmulons 12.
- K562: CORUM CLR (t = 0; no attention depth beats CLR), KD-response modules 24, DoRothEA A-B 4, DoRothEA A-C 8, CollecTRI 48.

For comparison, the linear-grid run gave E. coli 4, 32, 13 and K562 0, 26, 4, 7, 32. The two grid-edge cases of that run moved to 96 (E. coli TF regulons) and 48 (K562 CollecTRI). The Spearman values on the linear grid (0.5 and 0.7, computed exploratorily before the preregistration) are the same as the new ones.

## Deviations from the preregistration

None of these changes the statistics, truths, grid, operators or readings. Each is listed with its timing relative to the results.

1. **Memory (infrastructure), decided after the E. coli and K562 sweeps had completed but before any bootstrap result existed.** The first job runs were OOM-killed when the bootstrap forked 8 workers: R sets its garbage-collection threshold from the large parent heap (3-20 GB after the walk), so each forked worker accumulated gigabytes of dead 26-100 MB vectors (3-12 million pairs per truth, 17 depths) before collecting. The earlier linear-grid job had no bootstrap and held no per-depth orderings, so it was far lighter. Fix in `analysis/granularity_log.R` (commit 512c6b2): `gc()` in the parent before the fork and `gc(FALSE)` after every depth in the workers. Results do not depend on it (curves byte-identical across runs).
2. **File names and code** differ from section 11 of the preregistration: curves in `curves_{ecoli,k562}.csv`, bootstrap draws in `boot_{ecoli,k562}.csv.gz`, sizes in `truth_sizes_*.csv`, statistics in Python (`analysis/depth_log_analysis.py`) rather than R. The analysis script was written after the preregistration commit and before any new result.
3. **Seed handling made concrete:** `set.seed(20261015)` at the start of the bootstrap of each organism, draws generated per truth in the order of the truth list (the preregistration says "same seed" and "draws per truth in order").
4. **K562 sweep ran twice** (the first run was killed at its bootstrap by the memory error above, the retry reran everything); the curves are identical, so nothing was selected between runs. The same holds for E. coli.
5. Nothing was changed after the first result: no truth, operator, grid point, statistic or reading rule.
